## 1. 一句话结论

导出髋部垂直幅度只有视频的 **86%**，根因不是「腿没余量」，而是 **ExMR 单目估计把
「屈膝下蹲→顶髋伸直」的腿部屈伸律动估僵了**：它把本应靠腿屈伸贡献的骨盆起伏，错误地
转移成「膝盖/脚踝朝镜头方向的多余运动」，骨盆只能靠根平移抬升，而根平移又被弱透视整体
压缩。裁剪放大输入（800×800）无效甚至更差（86%→81%）。

## 2. 度量口径

- 2D 真值：`exmr_keypoints.pt`（COCO-63 布局），骨盆 2D = 左髋(11)/右髋(12)中点；膝盖=13/14、脚踝=15/16。
- 3D 关节：`exmr_results.pt` 的 `smplx_incam`/`smplx_global` 经 SMPL-X FK（`smplx.SMPLX(flat_hand_mean=False)`，`joints[:, :22]`）。
- 重投影：`u = fx·x/z + cx`，`v = fy·y/z + cy`。
- 内参：960 工程 `fx=fy=1357.6, cx=cy=480`，骨盆深度均值 3.09 m，1 m ≈ 439 px；800 工程深度 2.63 m。
- 帧 118–150 = 4–5 s 的「左右晃髋 + 向斜上方顶」核心段。
- 验证脚本为一次性内联脚本（`runtime_exmr/python.exe` 跑，未落盘），复用
  `mocap/hip_motion.py` 的 `_body`/`_pelvis` 与自写全关节 FK，只读盘上产物，无 GPU 推理。

## 3. 误差账目（实测）

### 3.1 全链路垂直幅度（960 工程，骨盆）

| 阶段 | 垂直幅度 | 相对视频 |
| --- | --- | --- |
| 视频 2D 真值 | 64.60 px = 0.147 m | 100% |
| ExMR 相机系 `smplx_incam` 重投影 | 55.55 px = 0.123 m | **86%** |
| 世界系 `smplx_global`（rollout） | 0.1185 m（与视频相位相关 −0.109，基本不同相） | 81% |
| `follow_camera_root` 后（`hmr4d_results.pt`） | 0.1234 m（相位恢复同相） | 84% |
| correction 后（最终 `motion.bvh` Hips Yposition） | 0.1265 m | **86%** |

水平方向对照：视频 u ptp=121.59 px，相机系投影 122.49 px（**99.3%**）。**水平几乎完美、垂直系统性少 14%。**

裁剪放大（800 工程，`hip_motion=false`）：深度 3.09→2.63 m，但相机系骨盆重投影 v ptp
从 55.55 px 掉到 **47.32 px（79%）**，最终 BVH Hips Y 0.0936 m（视频真实 0.116 m，81%）。
**放大人物反而更差**，证伪了「人物太小」假设。

### 3.2 关节级不对称：髋被压缩、膝/踝被放大、肩正确

ExMR 相机系 22 关节重投影 vs COCO 关键点，垂直（v）幅度比：

| 关节 | 投影 v ptp | 2D v ptp | 幅度比 | 残差相关* |
| --- | --- | --- | --- | --- |
| 骨盆 hip中点(1,2) | 55.55 px | 64.60 px | 0.860 | −0.709 |
| 左髋(1) | 50.82 | 67.14 | 0.757 | −0.649 |
| 右髋(2) | 60.64 | 67.40 | 0.900 | −0.735 |
| 左膝(4) | 98.97 | 80.63 | **1.227** | −0.257 |
| 右踝(8) | 46.32 | 54.57 | 0.849 | −0.447 |
| 左肩(16) | 82.03 | 79.04 | **1.038** | +0.013 |

*残差相关 = 投影残差与 2D 真值（去均值）的相关，负值 =「高估低位、低估高位」的幅度压缩。

压缩不是全局的，而是集中在**髋→腿链**：髋 0.76–0.90、膝 1.227（放大 23%）、踝 1.234（放大 23%）、
肩 1.038（正常）。ExMR 把「髋部上下起伏」重新分配给了膝盖和脚踝的垂直运动。

### 3.3 腿部几何：屈伸律动被腰斩

垂直投影长度（v 向下为正，「大腿长 = 膝v − 髋v」）：

| 量 | 视频 2D | ExMR 投影 | 比值 |
| --- | --- | --- | --- |
| 大腿长（髋→膝）全段 | 43.85 px | 36.47 | 0.832 |
| 大腿长（4–5s） | 24.52 px | 12.43 | **0.507** |
| 小腿长（膝→踝）全段 | 50.23 | 39.74 | 0.791 |
| 全腿（髋→踝）全段 | 68.49 | 70.16 | **1.024** |

决定性相位证据：

```
大腿垂直投影长度 与 骨盆v 的相位相关：
  视频 = −0.668   （骨盆上提时腿伸直、下蹲时屈膝）
  ExMR =  0.011   （腿几乎不随骨盆起伏屈伸 —— 僵直）
```

视频 4–5s 骨盆上提 58.8 px 的构成：脚踝 23.5 px + 髋−踝（屈膝伸直）41.1 px。ExMR 只还原了
髋−踝 33.0 px（0.805），缺失的 8.0 px 被脚踝多动的 7.7 px 顶替（4–5s 脚踝幅度比 1.329）。
**ExMR 正确还原了「髋到脚踝」的总长度（1.024），但把中间的髋/膝/踝三点位置分配错了。**

## 4. 根因（分层）

1. **源头：ExMR 相机系把「腿屈伸」估没了。** 视频的「顶髋」是「屈膝下蹲→蹬直顶髋」的
   屈伸律动（大腿屈伸 24.52 px @4–5s），ExMR 只还原 12.43 px（0.507）。腿被锁死在近似伸直、
   不随骨盆屈伸的僵姿（`smplx_incam` 的 `body_pose` 已把腿估成接近伸直）。

2. **ExMR 的膝盖弯曲方向错：朝镜头而非垂直下蹲。** ExMR 膝盖 3D 屈伸角全段 ptp = 77.6°（它在动，
   不是完全僵直），但垂直投影大腿长与骨盆v相关仅 0.011。即 ExMR 用「膝盖前后弯（朝镜头）」
   错误解释了「髋部上下起伏」，2D 上几乎不体现，髋部起伏因此被压掉。

3. **`follow_camera_root` 忠实继承 86%。** `mocap/hip_motion.py:122` 的 `_camera_path` 对垂直
   `camera[:,1]` 原样保留，相机系少多少世界根就少多少。

4. **幅度被二次锁死在 86% 的代码原因：`bob` 语义被改掉。** `mocap/hip_motion.py:273`
   `scale_excursion(followed, sway, 1.0)` 把垂直增益写死 1.0（「垂直不再缩放，交给 bend」）。
   实施计划把 `hip_bob_gain` 从「垂直增益」改成「屈膝深度 0–1」，垂直方向再无补幅手段。

5. **`bend` 的「脚底贴地」目标与视频不符。** 视频全段脚的运动比骨盆还大（脚踝 76.60 px、
   脚跟 78.29 px、脚趾 77.34 px，全部 > 骨盆 64.60 px）。视频里人物脚本来就在大幅抬/跺/踮，
   「脚踩住、只动髋」只是 4–5s 的局部现象。bend 强迫贴地，既没贴住（960 工程 correction 后
   脚底仍动 0.098 m），也没补足幅度。

6. **裁剪放大无效：** 深度变近（3.09→2.63 m）的投影放大，被网络对 `ty`（box 内垂直偏移）更
   严重的低估抵消（87%→79%）。box 被画面边界钉死后（box 中心垂直 ptp 从 66.59 px 降到 16.80 px），
   更多垂直表达压到 `ty`，低估更重。

## 6. 修复方案

### 6.1 短期（先落地，直接解决「幅度不够」）

恢复根平移垂直增益，并用 2D 真值自动校准：

- `match_video` 里 `scale_excursion(followed, sway, 1.0)` 的垂直参数放开，与 bend 解耦、顺序叠加
  （先补幅度，后（可选）屈膝）。
- 增益值从 `exmr_keypoints.pt` 自动反算，不人工调：`bob = 视频骨盆v_ptp / 相机系骨盆投影v_ptp`
  （本片 ≈ 64.60/55.55 = 1.16；按 transl.y 口径 ≈ 0.147/0.123 = 1.20）。
- 位置：exmr 阶段、写 `hmr4d_results.pt` 前；纯 numpy，无 GPU、无重训。

**预期**：髋部垂直幅度 86%→100%。代价：腿的「屈伸律动被腰斩 / 朝镜头弯」仍在（这需要 6.2）。

### 6.2 长期（同时修幅度 + 腿僵 + 朝镜头弯）

以视频 2D 关键点做 ExMR 3D 输出的二次监督重拟合：

- 目标：`Σ 加权(重投影 − 视频2D)² + 腿长守恒软约束 + 深度正则`
- 优化变量：膝盖屈伸角（绕身体左右轴 sagittal）+ 每腿深度
- 产出：替换 ExMR 估僵、朝镜头弯的 UpLeg/Leg 旋转，恢复「屈膝下蹲→顶髋伸直」律动

可行性见第 7 节。

## 7. 2D 几何驱动可行性验证

### 7.1 四个实验（960 工程，左腿）

**实验 1：2D 与 ExMR 深度的自洽性（腿长守恒）**

| | 视频2D+ExMR深度反投影 | 物理腿长（ExMR FK） | 偏差 |
| --- | --- | --- | --- |
| 大腿 | 0.4330 m（std 1.97cm） | 0.3941 m（std 0） | +3.89 cm |
| 小腿 | 0.4055 m（std 1.35cm） | 0.4125 m（std 0） | −0.7 cm |

ExMR 腿长完全恒定（SMPL 骨骼刚性 std=0）；视频 2D 反投影腿长有波动，与物理不自洽。

**实验 2：固定髋深度反解膝盖（射线-球相交）** —— 271/301 帧无解。解析反投影不可行。

**实验 3：无解原因（角距离诊断）**

| 量 | 视频2D角距离×髋深度 | 物理 | 比值 |
| --- | --- | --- | --- |
| 大腿（髋→膝） | 42.48 cm | 39.41 cm | **1.078**（272/301 帧超长） |
| 小腿（膝→踝） | 41.12 cm | 41.25 cm | **0.997** |

大腿角距离系统性偏大 7.8%，且与骨盆v相关仅 0.042（常数偏置，非随动作耦合）；std 2.77 cm（2D 噪声）。
小腿几乎自洽。**偏差集中在大腿段** —— 即 COCO knee 关键点标在「髌骨前下方」、SMPL knee joint
在「股胫连接中心」的定义差。

**实验 4：ExMR 膝盖弯曲方向** —— 3D 屈伸角 ptp 77.6°（在动），但垂直投影大腿长相关 0.011
（视频 −0.668）。**ExMR 的膝盖弯曲朝镜头（前后），不是垂直下蹲。**

### 7.2 障碍清单

| 障碍 | 量化 | 解法 |
| --- | --- | --- |
| ① COCO knee 与 SMPL knee 定义差 | 大腿角距离偏大 7.8% | 关节偏移校正，或腿长守恒改软约束（±8% 弹性） |
| ② 2D 关键点噪声 | 角距离 std 2.77 cm | 2D 对齐用加权软目标 + 时间平滑 |
| ③ ExMR 膝盖朝镜头弯 | 3D 屈伸 77.6° 但垂直投影不动 | IK 强制弯曲轴 = 身体左右轴（sagittal），禁止朝镜头 |
| ④ 单目深度歧义 | 深度 3 自由度只被 2 约束 | 深度作自由变量 +「接近 ExMR 深度」正则 |

① ② 是既有文档没料到的新障碍；③ 坐实了交接文档 §6.5 的「膝盖朝镜头弯」预警；④ 是单目固有。

### 7.3 可行性结论

**2D 腿部几何驱动：可行，但必须做成「带约束优化」，不能走「解析反投影」。**

- 2D 腿部几何确实包含屈膝律动信息（视频大腿投影长与骨盆v相关 −0.668，ExMR 为 0.011）。
- 预期收益：4–5s「髋−踝」屈伸律动从 33.0 px 恢复到 41.1 px（现 0.805），配合 6.1 的根平移增益，
  髋部幅度回到 ~100%，且腿不再朝镜头弯。
- 代价：一次完整优化求解（比 bend 的解析 IK 复杂一个量级），需权衡 2D 对齐 / 深度正则 / 屈伸方向约束。
  回归风险：膝盖 2D 误差（验收线沿用交接文档 §6.4：不比 bend 差 10 px 以上）。

## 8. 建议与下一步

1. **先做 6.1**：根平移垂直增益自动校准，成本最低、直接解决「幅度不够」；bend 暂关。

3. **不要再试**：裁剪/放大输入（已验证 86%→81%）；单纯加大 bob（只改幅度不改「整体抬升 vs 屈膝」比例）；
   脚底贴地（视频脚部运动本就大于骨盆，目标证伪）。
4. 落地 6.1 后需重跑 exmr 阶段（`hip_motion.py` 哈希进签名，开关打开态会重算），并回归 `women_dance`（658 帧）。
