## 2. 总结论

问题不是视频分辨率，也不是 BVH 导出造成的二次衰减，而是三层原因叠加：

1. **ExMR 原始世界根轨迹错误**：世界根由速度头积分得到，静态相机修正只处理部分慢漂移，快速垂直节奏可以与视频明显不同相。
2. **当前实现取消了垂直幅度补偿**：原来的 `hip_bob_gain` 被改成 0–1 的“屈膝深度”，而 `match_video()` 将真正的垂直增益固定为 1.0。屈膝只改变姿态和脚部分解，不会增大根轨迹幅度。
3. **现有屈膝 IK 存在大量不可达约束**：脚踝目标、骨盆目标和固定腿长在不少帧无法同时满足。当前代码没有进行可行的逐帧根轨迹规划，却仍按可达目标求解，因此“脚踝精确贴地”和“骨盆相对脚充分上提”都没有得到保证。

因此，继续裁剪视频、只调膝盖朝向、只缩短脚底低通窗口，或继续增加 bend，都不能解决根本问题。

## 3. 数据链与责任边界

当前处理链为：

```text
ExMR 相机系结果（图像拟合）
    ↓
ExMR 世界系结果（根速度积分、静态关节/相机修正、全局平滑）
    ↓
mocap/hip_motion.py：世界根跟随相机系根
    ↓
水平幅度缩放；垂直增益当前被固定为 1.0
    ↓
absorb_vertical()：动态地面、根整体下移、两骨 IK 修改 body_pose
    ↓
correction：balance、可选脚部接触修正等
    ↓
BVH / 预览 / 角色重定向
```

必须把三个目标分开：

- **根跟随**：解决世界轨迹与画面不一致。
- **垂直增益**：补偿相机系估计本身偏小的幅度。
- **屈膝吸收**：在脚部约束下改变骨盆与脚的相对运动，不负责放大根轨迹。

现有实现把后两个目标合并到一个参数中，导致责任边界丢失。

## 4. 根因一：原始世界根轨迹与视频不一致

`third_party/ExMR/exmr/model/global_traj.py` 中的世界根来自 `local_transl_vel` 的积分。静态相机分支的 `static_cam_transl()` 使用约 2 秒高斯参考和 0.25 m 死区，只去除超过死区的慢速偏差，不会把快速垂直运动直接替换为图像拟合轨迹。

原始、关闭髋部处理的数据验证：

- 4–5 秒世界骨盆垂直 ptp 约 **2.0 cm**，参考文档按视频折算的目标约 **12.5 cm**。
- 世界根垂直轨迹与视频的相位相关性约 **0.121**。
- 相机系骨盆二维轨迹与视频的垂直相关性约 **0.92**。
- 相机系 13 关节平均重投影误差约 **17.9 px**，明显优于原始世界轨迹。

因此，参考文档采用相机系根替换世界根的方向是正确的；问题不能完全归结为“网络没有恢复动作”，还包含世界轨迹生成和后处理的信息丢失。

## 5. 根因二：相机系估计仍偏小，800×800 没有改善

即使不看错误的世界根，相机系结果也没有完整达到视频二维幅度：

| 数据 | 视频二维髋部垂直 ptp | ExMR 相机系骨盆二维 ptp | 比例 |
| --- | ---: | ---: | ---: |
| 原始 960×960 | 64.6 px | 55.6 px | 约 86% |
| 裁剪 800×800 | 59.9 px | 46.4 px | 约 77% |

800×800 实验没有带来有效的人物放大：

- 原工程跟踪框平均高度约 **837 px**。
- 裁剪工程跟踪框平均高度约 **794 px**。
- 裁剪后人物更接近画面上下边界，窗口内脚踝关键点置信度略低。
- 裁剪工程仍关闭 `hip_motion`，原始世界根积分问题也仍然存在。

所以“人物占画面比例更大”不等于“模型获得更多有效像素或更可靠深度”。裁剪不能修复世界根算法，也没有改善本例的相机系垂直估计。

## 6. 根因三：垂直增益被参数语义改造移除

当前 `mocap/hip_motion.py:273`：

```python
followed = scale_excursion(followed, sway, 1.0)
```

垂直增益被固定为 1.0。UI 和配置中的 `hip_bob_gain` 已变成 `Knee Bend`，取值 0–1，并作为 `absorb_vertical(..., bend)` 传入，而不再控制垂直幅度。

使用当前生产函数对同一原始记录做内存验证：

| 操作 | 根 Y ptp |
| --- | ---: |
| 相机系根跟随，不增益 | 0.123392 m |
| 旧逻辑独立 `bob=1.2` | 0.148071 m |
| 当前 `bend=0` | 0.123392 m |
| 当前 `bend=1` | 0.123392 m |

`bend=0` 与 `bend=1` 的根差异仅为恒定的 **−0.135685 m** 整体偏移，逐帧差异的 ptp 为零；主要变化发生在 `body_pose`。

结论明确：**当前 bend 不会、也不可能补偿根轨迹的垂直幅度。** 全段幅度仍偏小，是参数语义改造后的直接结果，而不是 IK 弯曲程度不够。

## 7. 根因四：现有屈膝 IK 不满足几何可达性

### 7.1 动态地面不是接触锚点

`mocap/hip_motion.py:232-233` 从当前双脚最低关节生成 `foot_low`，再进行 0.3 秒高斯低通，作为双脚共同地面目标。

该值来源于已经被根跟随修改过的身体位置，因此不是独立地面观测：

- 根整体移动时，脚底和 `ground` 也会移动。
- 双脚没有按接触/摆动状态区分。
- 脚跟、前掌滚动和单脚支撑没有被独立表达。
- 对 `women_dance` 这类位移、转身片段，强制双脚贴向共同地面会破坏原有脚步。

### 7.2 不可达时截断距离并不能实现脚踝目标

当前数据按生产目标重新计算：

| 项目 | 左腿 | 右腿 |
| --- | ---: | ---: |
| 全段不可达帧 | 170 / 301 | 62 / 301 |
| 4–5 秒不可达帧 | 13 / 33 | 8 / 33 |
| 最大脚踝目标误差 | 9.72 cm | 5.30 cm |

两骨 IK 中虽然截断了距离标量，但仍保留原始不可达脚踝目标。固定骨长条件下，骨盆和脚踝同时不变时，超过腿长的目标没有解。截断计算中的距离不会创造可伸余量，也不能保证脚踝落在目标上。

### 7.3 当前“根高度回退”不能修复相对可达性

`mocap/hip_motion.py:243-246` 先将整段根向下移动一个常量，再根据移动后的脚底重新计算 `ground`。

这会使根、地面和脚踝目标一起下移，髋—踝相对距离基本不变。因此它：

- 不改变根轨迹 ptp；
- 不消除不可达帧；
- 主要只改变整段绝对高度；
- 不能实现注释中所述的可达性保底。

### 7.4 当前视觉问题需要拆成“根”和“相对脚”两部分

当前开启髋部处理的情人节结果，在 4–5 秒窗口约为：

| 指标 | 当前结果 | 参考文档的视频折算值 |
| --- | ---: | ---: |
| 骨盆 Y ptp | 12.3 cm | 12.5 cm |
| 脚趾 Y ptp | 5.7 cm | 3.4 cm |
| 骨盆−脚趾 ptp | 7.2 cm | 9.1 cm |

因此当前核心段的根抬高本身已接近目标；视觉仍显弱的主要原因是**脚也跟着上下、骨盆相对脚的屈伸不足**。全段最大根幅度则还受到垂直增益被移除的影响。

## 8. 导出与角色重定向复核

### 8.1 源 BVH 没有额外压缩根幅度

当前开启工程中：

- `corrected_initial.pt` 的根 Y ptp：**0.126509 m**。
- `corrected_initial_motion.bvh` 的根 Y ptp：**12.6509 cm**。
- 对应 rig BVH 的根 Y ptp：**0.126509 m**。

三者一致，说明当前幅度不足不是 BVH 写出阶段造成的。

### 8.2 “角色重定向无损”不是普遍成立的结论

`mocap/retarget/pipeline.py:29-31` 根据目标角色与源骨架的腿长计算 `ratio`，并用它缩放根位移。短腿角色的髋部位移按较小比例显示是现有设计的一部分。

因此：

- 源骨架 BVH 可以逐帧保持一致；
- 自定义角色的视觉幅度应结合腿长比例比较；
- 不能把源 BVH 无损直接推导为所有角色重定向后的米制位移无损。

本次没有实际角色重定向缓存，因此没有测得某个具体角色的 ratio，也不主张重定向是本例的主因。

## 10. 建议修复方案

### 10.1 第一优先级：恢复独立垂直增益

恢复两个正交参数：

- `hip_bob_gain`：垂直根幅度增益，恢复原来的有效范围和含义。
- 独立的 `hip_knee_bend`：0–1，仅控制屈膝吸收和脚部约束比例。

建议处理顺序：

```text
相机系根跟随
→ 水平/垂直幅度增益
→ 逐帧可达性与接触规划
→ 屈膝 IK
→ correction
→ 导出/重定向
```

增益必须位于 IK 之前。先固定脚再放大根，会再次把脚整体抬起。

配置兼容方面，不应继续复用同一字段表达两种语义。新字段需要明确版本；旧工程按配置版本或 receipt 识别旧含义，避免再次静默迁移。

### 10.2 第二优先级：先规划可行根轨迹，再求两骨 IK

每帧、每腿先检查髋—踝目标距离：

- **可达**：使用单位髋踝方向和正确极点求精确两骨解。
- **不可达**：必须显式选择并记录权衡：
  - 平滑降低/调整骨盆目标，使支撑脚保持接触；或
  - 保留骨盆目标，放松脚部约束并允许离地/滚动。
- 将不可达修正分散到时间窗口中，避免单帧根跳动和膝盖翻转。
- 输出每腿不可达帧、根修正量和脚踝残差，不能把截断求解报告为精确命中。

固定腿长下，“任意骨盆高度 + 双脚严格固定”并不总是有解。这是必须显式处理的物理约束，不是继续调参可以消除的数值噪声。

### 10.3 第三优先级：接触感知脚部目标

- 按左右脚分别维护接触状态、支撑锚点和摆动状态。
- 支撑阶段使用稳定地面/接触轨迹，不再使用由当前整体根位置推导出的共同动态地面。
- 保留脚跟、前掌滚动及合理脚尖抬升。
- 摆动脚保留源运动，不参与强制贴地。
- 位移、转身片段必须通过 `women_dance` 回归；不能只针对正面原地律动调参。

### 10.4 不建议继续作为主要修复方向的尝试

- 再次裁剪或放大输入视频：本例已实测更差，且不改变世界根算法。
- 只提高 bend：不增加根幅度，也不能解决腿长不可达。
- 只调 `SOLE_SECONDS`：动态地面仍与根耦合。
- 只调膝盖朝向/低通：可以改善翻转或观感，但不能修复目标不可达。
- 只加大 bob 并保留当前 IK：可能增加不可达帧和脚部误差，必须先有可行轨迹规划。
- 用角色重定向比例补偿源动作：会混淆源数据正确性和角色比例，不应作为根因修复。

## 11. 验证与验收建议

每次验证都应分阶段保存指标，而不是只观察最终动画：

```text
native world
→ native incam
→ follow
→ bob gain
→ 可达性规划 + knee IK
→ correction
→ source BVH
→ character retarget（如使用）
```

### 11.1 参数职责测试

- `bob=1.2` 时，增益后根 Y ptp 应为增益前的 1.2 倍。
- 固定 bob，改变 bend 时，根轨迹形状和 ptp 不应被 bend 当作增益改变。
- bend 的主要作用应体现在脚踝残差、骨盆相对脚和膝关节屈伸上。

### 11.2 情人节核心指标

分别报告全段和 4–5 秒：

- 根/骨盆 Y ptp；
- 左右脚踝、脚趾 Y ptp；
- 骨盆相对支撑脚的 ptp；
- 二维骨盆、膝盖、脚踝重投影误差和相位相关；
- 每腿不可达帧、根回退量、脚踝目标残差；
- correction 前后的变化，避免把 balance 的影响混入 IK 判断。

### 11.3 通用回归

- `women_dance`：转身、位移、单脚支撑和摆动脚不得因双脚强制贴地而劣化。
- 源 BVH 与选中结果的根通道继续保持一致。
- 使用自定义角色时，同时报告腿长 ratio 和归一化后的根幅度。

## 12. 最终判断

当前问题可以概括为：

> **原始世界根轨迹需要替换；替换后的相机系根仍需独立幅度补偿；屈膝吸收必须建立在接触感知且几何可行的根轨迹上。**

现有代码只较好地完成了第一部分，并把第二部分的参数改成了第三部分；第三部分又缺少不可达处理。因此，最小且正确的修复不是继续调 IK 常数，而是先恢复独立 `bob` 增益，再重做逐帧可达性和接触目标规划。
