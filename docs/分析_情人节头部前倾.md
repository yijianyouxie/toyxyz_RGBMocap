## 1. 结论

**头部前倾来自 ExMR 的原始姿态（`body_pose` 里 Neck、Head 两个关节的局部旋转），不是重心修正、膝盖重建、脊柱拉直或导出 retarget 造成的。**

| 量 | 情人节 | women_dance |
| --- | --- | --- |
| 颈关节局部前俯（相对 Spine3） | **+18.0°**（p95 +29.8） | +1.6°（p95 +21.1） |
| 头关节局部前俯（相对 Neck） | **+16.5°**（p95 +23.6） | +3.9°（p95 +16.5） |
| 头骨上轴相对胸廓的前俯角 p（第 2 节口径） | **中位 +37.5°，91% 帧 >15°** | 中位 +3.5° |
| 导出 BVH 的 Head 骨骼世界俯仰 | **均 +36.9°** | 均 +4.9° |
| 头心相对颈基的前向偏移 | +6.5 cm（rest +2.0 cm） | +2.4 cm |

同一段视频用 flowHMR 重建，头骨相对胸廓的中位仍是 **+26.7°**；而库里其余 6 个项目、3 个引擎共 15 条结果，中位数全部落在 **−13.4° ~ +14.6°**。

所以：**这不是某一个模型的 bug，而是这个片段把「颈-头俯仰」这条弱可观测的自由度推到了极端**（第 4 节的机制判断），表现为整段恒定的前倾偏置，而不是某几帧低头。

## 2. 度量口径

人体矢状面俯仰一律用**胸廓自身坐标系**，不用世界轴（人物会转身，世界 Z 不可靠）：

```
u_c = R9  · (0,1,0)      # 胸廓（Spine3）上轴
f_c = R9  · (0,0,1)      # 胸廓前向
u_h = R15 · (0,1,0)      # 头骨上轴（R15 为第 15 关节的全局旋转）
p   = atan2( u_h·f_c , u_h·u_c )    # 头相对胸廓的前俯角，正 = 向前
```

- `p` 只反映**姿态叠加**的俯仰：rest 时 R9=R15=I，p=0，SMPL-X rest 自带的角度不进入该量。
- 位置另用一个量：头心相对颈基的前向距离 `(J15−J12)·f_c`。
- 数据来源：`initial_joints.npz`（原始结果）与 `corrected_initial_joints.npz`。

- p 与「头相对颈的局部 yaw」相关 0.14、与 |头 yaw| 相关 0.01。**不是「转头时才准、正面时才偏」**，而是无论朝向都偏。

## 4. 为什么 women_dance 没事

1. 数值：p 中位 +3.5°，导出 BVH 头骨 4.9°，头心相对颈基 +2.4 cm ≈ rest 的 +2.0 cm —— 与静息姿态一致。
2. 外观：无发、无遮挡、轮廓清晰的灰白人偶，颈段裸露，比例接近 SMPL-X 默认值，图像证据足以把俯仰钉在 0 附近。
3. 情人节是风格化 CG 角色：**发量 + 头顶大蝴蝶结**让头部剪影远大于颅骨，脸小且无五官细节，再加高领/颈环遮挡颈部边界。模型只能用「略低头」的平均先验去解释这块剪影，于是整段落在 30–45°。

> 机制判断：正面（相机与人体前向接近平行）时，绕侧向轴的颈-头俯仰几乎不改变 2D 投影（位移主要沿视线方向），是单目重建的典型退化方向；外观证据一旦变弱，回归器就回落到先验。这与重心修正处理的「腿长深度歧义」是同一类问题，只是发生在颈段。

## 5. 方案：颈部俯仰回正（片级偏置）

### 5.1 为什么不用「逐帧钳制」

逐帧把 p 钳到上限会**压缩真实低头**：women_dance 有 31% 的帧 p>15°（真实低头/甩头），钳到 15° 会把 34° 的真实低头压掉 19°；钳制边界还需要平滑 + 限速（膝跳那一套），实现复杂、副作用大。

本片的问题是**整段恒定偏置**（3.4 节），因此用「片级常量」最贴合：加性常量不产生任何时域伪影，也不需要限速。

### 5.2 算法

```
输入：22 关节全局旋转 R (T,22,3,3)

1) p(t) = atan2( (R15·Y)·(R9·Z), (R15·Y)·(R9·Y) )     # 头相对胸廓前俯
2) b = clip( median(p) − 10°, 0, 25° )                 # 片级偏置
   若 b ≤ 0 → 原样返回（逐位不变）
3) axis(t) = normalize( (R9·Y) × (R9·Z) )              # 该帧胸廓侧向轴
4) 每帧：
     R12 ← Rot(axis, −0.45·b) · R12                     # 颈
     R15 ← Rot(axis, −1.00·b) · R15                     # 头（子节点继承颈的旋转）
5) 由全局旋转反解局部旋转，写回 body_pose[11] (Neck) 与 body_pose[14] (Head)
```

要点：

- **头要按 `−b` 而不是 `−0.55b` 旋转**：R15 是 R12 的子节点，只转 R12 时头会跟着转；若再把头只转一半，实际只回正一半（本轮踩过：p 只降 5° 而不是 10°）。
- `0.45 / 0.55` 的分摊依据：该片段「骨轴（决定头的位置）」超出 rest 约 15°，「头骨朝向」超出约 19°，按这两份超额分摊，颈与头各承担一半左右，回正后颈不折、头不僵。
- 阈值 10°：库里 15 条结果的 p 中位最大 +14.6°，取 10° 时只有 last_year_summer 会被削 0.1–4.6°，其余全为 0。
- 上限 25°：约束最坏情况（整段真实低头的人最多被回正 25°）。

### 5.3 挂载位置与开关

- **位置**：`mocap/correction.py` 的 `run()`，在 `correct_arrays` 之后、写 `corrected_initial.pt` 之前修改 `body_pose`。这样 joints / BVH / FBX / 预览全部自动跟上，不需要第二处改动。
- **必须在 balance 之后**：`body_com` 含 Head 关节（权重 0.081），头后移会让 COM 后移约 3 mm；放在 balance 之后，`balance_*` 报告逐字段不变。
- **开关**：建议挂在现有的 `spine`（Straighten Spine）下 —— 它的 tooltip 本来就写着「Removes the permanent forward kink in the spine **and neck** bones」，语义一致，且不需要动网页端/桌面端 UI。代价是无法「只回正头、不拉直脊柱」。
  若要独立开关，则新增 `head`（默认 true），需同步 `correction_settings.correction_options`、`templates/index.html`、`app.py`、`exmr_pipeline.py --head`、`workspace_ui.py`、`people_ui.py` / `worker.py` 透传。
- **缓存**：`correction.py` 已在 `flow_correction.code_identity()` 与 `mixamo_data.code_identity()` 的哈希表里；且 `result_is_current` 会把 `correction_report.options` 与 `effective_options` 全量比对（`motion_tools.py:150`），翻转 `spine` 也会让旧的 `corrected_initial` 失效。两条路径都不需要 bump `VERSION`。

## 7. 残留与取舍

1. 修正后 p 中位仍有 +12.5°，视觉上是「轻微前倾但自然」；想更狠可把上限提到 30°（头心再后移约 1 cm，开始有「军姿」感）。旋钮就是 `MAX_OFFSET`，建议先 25° 看片再定。
2. 对「整段真实低头」的素材（看书、看手机）会过度回正，最多 25°。本库现有素材没有这种情况。
3. 只改 Neck/Head 的旋转，不改头的位置目标；COM 会偏 3 mm（在 balance 之后施加，报告本身不变）。
4. 与本问题独立的一条：情人节 take 是 `spine=false`，导出 bind 仍带 SMPL-X 胸椎狗腿（spine2→spine3 前折 26°、spine3→neck 回折 11°，见 `source_animation.straighten_spine` 注释）。它加重「上身前倾」的观感，但**不影响本次的头骨角度**（骨轴朝向由旋转决定，bind 只影响关节位置）。用户重跑时一起打开 `spine` 可以叠加。
5. 本轮是离线验证（关节 + SMPL-X 网格侧视），没有跑 `correction.run` + `export_project` 真实链路，也没有出 FBX/BVH 视频。落地后必须补：真实链路两片同时跑、导出 BVH 头骨俯仰复测、看 FBX 视频（同交接文档第 10 节第 3/4 条）。

### 9.2 落地时踩到的两个坑

1. **`correct_arrays` 返回的四元数是局部旋转，不是全局**。第一版直接当全局算 p，量到的是「头相对颈」的局部角（16.4°），偏置只算出 6.4°。必须按 `PARENTS` 先合成全局链再测，改完再反解回局部（`L12 = R9ᵀR12`、`L15 = R12ᵀR15`）。修正后 `head_pitch_before_median_deg` 与离线分析的 37.54° 完全对齐。
2. **导出阶段有「上体局部旋转不得改变」的硬校验**（`mixamo_data.py` 的 Source correction changed inferred upper-body rotations）。它把 12/15 也算在上体里，第一版导出直接失败。处理方式与既有的 `hand_lock` 一致：只有当修正报告里确实记了 `head_posture` 且偏置 > 0 时，才把 12/15 从 `preserved_joints` 排除，并把偏置写进导出报告；其余关节仍严格比对（实测 `upper_body_rotation_max_deg = 7.5e-06`）。
